# Simulator webhooks

Each organization can configure one HTTPS endpoint for iOS simulator and Android emulator lifecycle notifications. Limrun sends JSON POST requests to that endpoint.

## Configuration

Organization administrators and API keys with the `organization:*:all` scope can manage the webhook. Instance tokens cannot manage it.

```bash
curl -X PUT https://api.limrun.com/v1/organizations/ORG_ID/instance_webhook \
  -H "Authorization: Bearer $LIM_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://your-app.example.com/limrun/events"}'
```

Replace `ORG_ID` with your organization TypeID, starting with `org_`. The response contains `url` and `signingSecret`. Save the secret securely; subsequent reads omit it.

| Method | Path | Behavior |
| --- | --- | --- |
| `PUT` | `/v1/organizations/{organizationId}/instance_webhook` | Sets the URL and generates a new signing secret. |
| `GET` | `/v1/organizations/{organizationId}/instance_webhook` | Returns the URL, or `404` if no webhook is configured. |
| `DELETE` | `/v1/organizations/{organizationId}/instance_webhook` | Disables the webhook and discards pending deliveries. |

Every `PUT` rotates the secret, including when the URL stays the same. Pending deliveries use the current URL and secret. A delivery already in progress can finish using the previous configuration.

The endpoint must use HTTPS with a DNS hostname. Delivery rejects private, loopback, and link-local addresses. Redirects are not followed.

## Events

Configure the endpoint before creating simulators. Existing lifecycle history is not sent.

| Event | Meaning |
| --- | --- |
| `instance.created` | Limrun first records the simulator after assignment. `occurredAt` contains its creation timestamp. |
| `instance.ready` | Limrun records the simulator as ready. |
| `instance.terminated` | Limrun records termination. Billing and physical cleanup may still be pending. |

A create request that fails before assignment does not produce a webhook. Notifications can arrive late during an outage. Xcode builds, Gradle builds, billing, and registry operations are outside this webhook's scope.

```json
{
  "id": "9d6bc112-a44e-53cb-8a87-358c3feab95b",
  "type": "instance.terminated",
  "organizationId": "org_...",
  "instanceId": "ios_euna_...",
  "product": "ios",
  "occurredAt": "2026-10-09T12:00:00Z",
  "reason": "UserRequested"
}
```

`product` is `ios` or `android`. `reason` appears on termination events and uses `UserRequested`, `InactivityTimeout`, `HardTimeout`, or `Unknown`. Treat unrecognized reasons as `Unknown`.

## Signatures

Requests include `Limrun-Event-Id` and `Limrun-Signature`. The signature has the format `t=UNIX_SECONDS,v1=HEX_HMAC`.

Compute HMAC-SHA256 using the complete signing secret over the timestamp, a dot, and the exact raw request body. Verify the signature before parsing JSON. Reject timestamps outside a five-minute tolerance to limit replay of captured requests.

```javascript
import { createHmac, timingSafeEqual } from "node:crypto";

function verifyWebhook(rawBody, signature, secret) {
  const match = /^t=(\d+),v1=([a-f0-9]{64})$/.exec(signature ?? "");
  if (!match) return false;
  const [, timestamp, digest] = match;
  if (Math.abs(Date.now() / 1000 - Number(timestamp)) > 300) return false;
  const expected = createHmac("sha256", secret)
    .update(timestamp + ".")
    .update(rawBody)
    .digest();
  return timingSafeEqual(expected, Buffer.from(digest, "hex"));
}
```

Pass the unmodified request bytes as `rawBody`. Parsing and reserializing JSON can change the signature input.

## Delivery and retries

Return a `2xx` response after accepting the event. Limrun retries timeouts, connection failures, and other HTTP responses, up to 12 attempts. Retry delays start at 30 seconds and increase to a maximum of six hours. Invalid destinations and exhausted deliveries are discarded.

Retries keep the same event ID and payload. Store processed event IDs so duplicate deliveries do not repeat your application's actions. Delivery order is not guaranteed; use `occurredAt` and the event type when updating your state. There is no delivery history or manual replay API.
