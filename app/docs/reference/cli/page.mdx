# CLI reference

The `lim` CLI drives every Limrun instance type from Linux, Windows, or macOS. This page lists every command in `lim` 0.35.1 and the behavior they share. For a command's full flag list, run it with `--help`:

```bash
lim ios create --help
```

## Install and update

Install the `lim` package globally with npm, pnpm, or bun. The CLI needs Node.js 20 LTS or newer:

```bash
npm install --global lim
```

Run the same command again to update, and `lim version` to print the installed version.

## Authenticate

Every command that talks to Limrun resolves an API key in this order:

1. The `--api-key` flag.
2. The `LIM_API_KEY` environment variable. The CLI also reads it from a `.env` file in the working directory.
3. The key stored in `~/.lim/config.yaml` by `lim login` (browser sign-in) or `lim set-api-key`.

`lim logout` removes the stored key. Headless hosts such as CI runners and cloud agents should set `LIM_API_KEY` from a secret. A command pinned to a single instance through `set-instance` or the `LIM_<TYPE>_INSTANCE_*` variables needs no API key at all; see [Sandboxed agents](/docs/agents/sandboxed-agents).

## Target an instance

Device and build commands accept `--id <instance-id>`; `get` and `delete` take the ID as a positional argument instead (`lim ios delete <instance-id>`). Without an ID, they use the instance of that type you created last in the current workspace. The CLI records these per workspace in `~/.lim/last-instances.json`; a workspace is the current git repository or worktree unless you assign one with `lim set-workspace-dir`, `--workspace`, or `LIM_WORKSPACE`. See [The CLI's default instance](/docs/concepts#the-clis-default-instance).

Pass `--id` explicitly in scripts, CI, and agents that create more than one instance.

When the targeted instance no longer exists, device and build commands create a replacement automatically; pass `--no-create` to fail instead. `create`, `delete`, `list`, `get`, `logs`, `tools`, and `version` never create a replacement; they fail with not-found instead.

## Shared flags

Commands that act on instances share these flags. Account commands such as `lim login` and `lim skills install` take only some of them.

| Flag | What it does |
|---|---|
| `--api-key <value>` | API key for this command. Overrides the stored login and `LIM_API_KEY`. |
| `--json` | Print structured JSON instead of tables or plain text, where the command supports it. |
| `--quiet` | Suppress intermediate logs and print only the final result. |
| `--workspace <value>` | Workspace used to find the most recent instance when no ID is given. Defaults to the current git repository or worktree. On `lim xcode build` and `lim xcode test`, `--workspace` is the `.xcworkspace` passed to `xcodebuild`; use `LIM_WORKSPACE` there. |
| `--[no-]create` | Create a replacement instance when the target is not found. On by default. |
| `--[no-]daemon` | Route device commands through a background WebSocket daemon that starts on first use, so repeated commands reuse one connection. On by default; disable with `--no-daemon` or `LIM_DAEMON=false`. |

`lim session start` starts the same background connection explicitly for one instance, `lim session status` lists running sessions, and `lim session stop` stops one or all of them.

## Environment variables

| Variable | Read by | Meaning |
|---|---|---|
| `LIM_API_KEY` | Every command | Organization API key. |
| `LIM_WORKSPACE` | Every command | Workspace for resolving the default instance. |
| `LIM_DAEMON` | Every command | Set to `false` to disable the background connection daemon. |
| `LIM_DISABLE_TELEMETRY` | Every command | Set to any value, such as `1`, to disable CLI usage telemetry. |
| `LIM_IOS_INSTANCE_URL`, `LIM_IOS_INSTANCE_TOKEN` | `lim ios` | Drive one simulator by its API URL and instance token, without an API key. |
| `LIM_ANDROID_INSTANCE_URL`, `LIM_ANDROID_INSTANCE_TOKEN`, `LIM_ANDROID_INSTANCE_ADB_URL` | `lim android` | The same for an emulator; the ADB URL enables `lim android connect`. |
| `LIM_XCODE_INSTANCE_URL`, `LIM_XCODE_INSTANCE_TOKEN` | `lim xcode` | The same for an Xcode sandbox. |
| `LIM_GRADLE_INSTANCE_URL`, `LIM_GRADLE_INSTANCE_TOKEN` | `lim gradle` | The same for a Gradle sandbox. |
| `LIM_WEBHOOK_URL`, `LIM_WEBHOOK_HEADERS`, `LIM_WEBHOOK_LABELS` | `lim xcode build`, `lim gradle build` | Defaults for `--webhook-url`, `--webhook-header`, and `--webhook-label`. See [Build logs and webhooks](/docs/ci/build-logs-and-webhooks). |
| `LIM_SIGNED_UPLOAD_URL` | `lim xcode build`, `lim gradle build` | Default for `--signed-upload-url` when `--upload` is not set. |
| `LIM_KEYSTORE_PASSWORD`, `LIM_KEY_PASSWORD` | `lim gradle build` | Passwords for `--keystore`. See [Sign and publish](/docs/android/sign-and-publish). |
| `LIM_PLAYSTORE_ACCESS_TOKEN` | `lim gradle build` | Google access token for `--upload-to-playstore`. |
| `LIM_TUNNEL_TOKEN` | `lim tunnel run` | Tunnel token, in place of `--token`. See [Private tunnels](/docs/networking/private-tunnels). |
